# 节奏、镜头与数值（几个旋钮）

想改「游戏快慢 / 视角远近 / 钱的面额」，只动几个数，不用碰逻辑代码。

| 想改什么 | 旋钮 | 文件 | 现值 |
| --- | --- | --- | --- |
| 全局快慢 | `GAME_SPEED` | `src/config/GameConfig.ts` | `0.6` |
| 动画是否跟着变慢 | `ANIM_TIME_SCALE` | 同上 | `1 / 0.6`（动画跑真实时间） |
| 白天长度 | `DAY_DURATION` | 同上 | 66 秒 |
| 一局几夜 | `TOTAL_NIGHTS` | 同上 | 8 |
| 视角远近 | `Screen.WORLD_ZOOM` | `src/config/Screen.ts` | `1.85` |
| 地面铺装块宽 | `GROUND_TILE` | `src/scenes/GameScene.ts` | 640 |

## 全局节奏 `GAME_SPEED`

乘在每一帧的 `dt` 上，**一次**影响移动 / 攻击 / 工期 / 招募 / 昼夜循环——
整体同步放慢，不会出现「人走慢了、箭还在飞」的错位。

- `1.0` = 原速；现值 `0.6` ≈ 原速的 60%。
- 一局时长 ≈ `TOTAL_NIGHTS × DAY_DURATION ÷ GAME_SPEED` = 8 × 66 ÷ 0.6 ≈ **14.7 分钟**。
- 白天想更长改 `DAY_DURATION`；从黄昏预警到入夜还有 `DUSK_WARNING_TIME`（10 秒）留给玩家收工。
- 手感参考：`0.5` 很慢（适合看演出），`0.6` 现值，`0.78` 偏快。

### 唯一不跟着 `GAME_SPEED` 变慢的东西：逐帧动画

各实体的动画时钟写的是 `animClock += dt * ANIM_TIME_SCALE`。
如果这里也乘 `GAME_SPEED`，6 帧的走路循环会从 13fps 掉到 ~8fps，看起来一顿一顿。
改了 `GAME_SPEED` **不要**去动 `ANIM_TIME_SCALE`（它就是 `1 / GAME_SPEED` 的倒数补偿）。

## 镜头远近 `Screen.WORLD_ZOOM`

- 屏幕像素 → 世界坐标：`camZoom = fit × WORLD_ZOOM`，其中 `fit = min(窗宽 / 1280, 窗高 / 720)`。
- `WORLD_ZOOM = 1` 时正好看到整个 1280×720 设计框；`1.85` 时只看得到 `1 / 1.85 ≈ 692 × 389`
  设计单位——**视角收窄、物体变大**，也就是「镜头拉近」。
- 本机 3440×1369 窗口实测 `camZoom ≈ 3.52`，可见世界宽度 3440 ÷ 3.52 ≈ 978 设计单位
  （对应可见高度 ≈ 389）。屏幕越大看到的地面越宽，但**取景比例与 1280×720 窗口始终一致**。
- 建议范围 `1.0 ~ 2.0`：现值 `1.85`，地平线落在屏幕自上而下约 58% 处，
  上面留给天空/远景，下面 42% 是地面带；再大就看不到脚边的地面，移动时容易一头撞上怪。
- 视角一近，田/民居等**占地宽度**也要跟着收：
  `assets/bg/*` 由 `Assets.ts` 里的 `w` 定宽（水田 `lm_paddy_*` 190、盐田 `lm_saltflat_*` 470），
  同时 `GameConfig.MAP_LANDMARKS.*.width` 要同步改小，否则投银/开垦的判定范围会和画面不匹配。

## 城外地面为什么不「一格一格」

城外滩涂是一张 640×160 的图横铺满 7600 px，天然会出现 640 的重复节拍。
`GameScene.ts` 里用四招打散（都在 `GROUND_TILE` 那一段）：

1. **变体轮换**：`ground_beach_b` / `ground_beach_c`（堡内是 `ground_city_b`）随机替换底图；
2. **隔块水平镜像**：`node.scaleX = -1` 并把 `x` 挪回一格（这类图 `ax = 0`，翻转后内容会跑到左边）；
3. **每块 0~3px 纵向微抖**：只能往上抖，往下会露出底色缝；
4. **地物碎屑层**：`ground_decal_01~06` 单张小图按固定种子撒在地上，随机镜像/0.7~1.4 缩放/0.45~1.0 透明度。

种子是 `groundRand(n) = frac(sin(n * 127.1 + 311.7) * 43758.5453)`，纯函数：
同一局每次重绘结果一致（不会闪），但相邻两块取法不同。
缺哪张图就自动退回上一层（变体缺 → 用底图；碎屑缺 → 整个碎屑层不画），不会报错。

## 银两单位（1 两 = 最小面额）

- `SILVER_NAME: '两'` 只是显示用的单位名；**所有数值本身就是「两」**，没有更小的单位。
- 投银一袋的默认袋重 `SILVER_BAG: 2` 两，实际投出 `min(SILVER_BAG, 还差多少)` 两，
  所以最后一袋可能只投 **1 两**（这就是「最低单位 1 银两」的落点）。
- 花费/收益都是个位数到十几两：初始 **13 两**、招募 4、民居起造 6 / 升级 8 / 18、宗祠 9、
  东门 8、水门 7、开垦水田 6 / 盐田 7、敌台解锁 11 / 炮台 7、炮台升级 9、
  撒银退敌 2/4/12、灶户一趟背盐 6、城外拾盐包 4 / 漂木 2、歼敌 1/2/8、夜赏 4~15。
- 压低节奏的做法是**收支一起砍**：只有收益降、花费不降，前几夜会卡死在招募不起人；
  只有花费降、收益不降，中后期银两会溢出。要再整体压一档就按同一个比例同时改这两组。
- 改数值只改 `GameConfig.ts` 里对应的常量；HUD 的按钮文案已改成直接读这些常量，
  **不要**在 `HudLayer.ts` 里再写死数字。

## 两套坐标空间（HUD 为什么没被一起放大）

- **世界空间**：世界层按设计单位摆放，被摄像机整体放大 `WORLD_ZOOM` 倍。
- **UI 空间**：`View.size ÷ uiZoom`（`uiZoom = fit`，与 `WORLD_ZOOM` 无关），
  所以 HUD / 标题 / 结算界面始终 **1 单位 = 1 设计单位**，不会跟着镜头一起放大。
- UI 根节点调 `Screen.attachUi(node)` 抵消镜头放大；
  布局尺寸读 `Screen.uiWidth / uiHeight / uiOffsetX / uiOffsetY`
  （改动前叫 `width / height / offsetX / offsetY`，老代码不要再用旧的）。
- 两套空间换算：`Screen.uiToWorld(ui 单位)` / `Screen.worldToUi(世界单位)`。
  触摸判定、镜头跟随边界（`halfView`）都要用它换算。

## 改完怎么验证

```bash
python tools/inspect_scene.py     # 场景树首行会打印 VIEW / CAMZOOM
```

`CAMZOOM ≈ fit × WORLD_ZOOM` 即说明生效；再看几行 `SPR tex ... draw ...` 的显示尺寸，
就能确认世界层的物件确实变大、而 HUD 尺寸没变。

## 地平线以下：城前水面与倒影

画面被地平线 `GameConfig.GROUND_Y`（128）横切：**上面是城，下面是水**。

- 岸带：`WATER.SHORE_BAND`（26）——地平线往下这一小条还留着地面贴图，再往下才是水。
  水面上沿 = `GROUND_Y - SHORE_BAND`。倒影就绕这条线上下翻。
- 水色：从水面上沿的 `WATER.COLOR_TOP` 竖直渐变到画面底部的 `WATER.COLOR_DEEP`
  （贴水面处反天光，越靠底越深）。`WATER.RIPPLE_COUNT` 道横纹慢慢漂。
- 倒影：`reflectOf(parent)` 在挂点下面挂一个 `refl` 子节点，
  `y = -SHORE_BAND`、`scaleY = -WATER.REFLECT_SQUASH`、`opacity = WATER.REFLECT_OPACITY`。
  因为挂在**源挂点底下**，源挂点一动倒影自动跟着走，不用每帧同步。
  贴图复用同一张：`artInto(holder, id, mirror)` / `artAnimInto(..., mirror)`
  会在镜像挂点里再挂一份，切换贴图时一起换。

  挂点造的地方：地标、民居、宗祠、内/东门（`artInto` 的第三个参数）。
  闸门插销 `portcullisNode` 不挂——它会上下滑，倒影会飘起来。
- 底栏取消：`BOTTOM_BAR_HEIGHT = 0`。技能键改到右上角竖排，
  额外动作按钮与工作/提示/按键说明改到左上角一列——底下整条水面留空给倒影。
