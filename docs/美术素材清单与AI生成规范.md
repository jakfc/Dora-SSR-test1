# 《永昌堡：铁血筑城》美术素材清单与 AI 生成规范 v1

> 用途：把当前"代码画的纯色方块"替换为 AI 生成的手绘素材。
> 本文档是**唯一风格依据**：所有素材都必须从第 1 节「风格圣经」派生，否则不通过验收。
>
> 现状说明：全部画面目前由 `DrawNode` 画纯色多边形 + `Label` 文字构成（见 `src/entities/*.ts`、`src/scenes/GameScene.ts`）。
> 尺寸、颜色、锚点都直接抄自代码，保证生成出来的素材能"原地替换"。

---

## 0. 怎么用这份文档

1. 先读第 1 节，**把「通用风格前缀 + 负面提示词」固定成一个模板**（建议存成快捷短语）。
2. 每一张图 = `通用风格前缀` + 第 2 节里该条目的 `专属提示词` + `通用后缀`。
3. **同一个角色/建筑的所有帧，必须在同一次会话里、用同一张参考图（image-to-image / 角色一致性）生成**，不要分开重开。
4. 出图后按第 4 节命名，按第 5 节验收，不合格的**只重跑不合格项**，不要改动已通过项。

## 1. 美术风格圣经（Style Bible）

### 1.1 一句话风格

**明代浙南抗倭题材 · 扁平化国风厚涂（Flat Guofeng, semi-flat shading）**：中景正侧视图，清晰深色描边（`#1A202C`，1.5–2px），每块面最多 3 阶明暗，无写实噪点、无油画笔触、无 3D 渲染感、无日式赛璐璐高光。

- 时代考据：明嘉靖三十七年（1558）浙南温州永嘉场，石砌堡墙、瓮城、箭楼、水门；平民短褐、军户罩甲、倭寇浪人装束。
- 气质：**沉郁、坚毅、史料感的暖土色调**，不鲜艳、不萌系、不二次元。
- 参照物：见 `参考/` 目录（永昌堡照片、汤和信俗、拼字龙灯、明制服饰资料）——形制以参考图为准，上色以本文档色板为准。

### 1.2 画面规格

| 项目 | 规定 |
|---|---|
| 视角 | **正侧视（90° side view）**，所有单位朝向统一（角色默认朝右，敌方默认朝左） |
| 透视 | 无透视 / 极弱透视，建筑可带 10% 顶面倾斜示意 |
| 画布 | 32 位 PNG，**透明背景**，四周留 8px 安全边 |
| 锚点 | 一律**底部中心（脚底/地基中心）**对齐 |
| 分辨率 | 见各条目「画布尺寸」（= 代码显示尺寸 ×2，便于缩放与细节） |
| 阴影 | 不画投影；只在脚下画一层 20% 透明椭圆暗影（可选，单独一张图层） |
| 光向 | 统一**左上方主光**，右侧为暗部 |
| 文字 | **素材里不许出现任何文字**（含招牌、旗号）——文字全部由代码 Label 渲染 |
| 输出 | 每张素材单独文件；动画帧按 `_01_02_03...` 连续编号，帧数一致 |

### 1.5 一致性八条军规（违反即返工）

1. **一套色板**：只能用 1.3 的颜色及其 ±10% 明度变化。
2. **一条描边**：所有素材描边颜色 `#1A202C`、粗细一致（按最终显示尺寸折算约 1.5px）。
3. **一个光向**：左上来光，右侧压暗；不许有反光。
4. **一个视角**：正侧视；不许混入正面/斜视。
5. **一张参考图**：每个角色先出"标准立绘"（T-pose/中性站立），后续所有帧/所有职业变体都用它做 image reference / IP-Adapter / 角色 LoRA。
6. **一个种子**：同一批次固定 seed（建议记下 seed 号写进文件名注释）。
7. **一批出图**：同一角色的多帧一次生成（左右行走、攻击、受击），不要跨天分次。
8. **一律无文字、无背景**。

## 3. 动画帧与导出规范

| 项目 | 规定 |
|---|---|
| 帧序 | 文件名 `名称_动作_序号.png`，序号两位补零（`_01`…） |
| 帧率 | 行走 8–10 fps，攻击 12 fps，待机 4–6 fps（代码控制，出图只需按顺序给帧） |
| 帧对齐 | 同一动作所有帧**画布尺寸、脚底基线、身体中心**完全一致（关键！用同一参考图连帧） |
| 循环 | idle/walk 首尾帧要能衔接 |
| 命名 | `assets/sprites/{类别}/{对象}_{动作}_{帧}.png` |
| 图集 | 也可导出 TexturePacker 图集（Dora SSR 支持），命名 `xxx.atlas` |

## 6. 文件尺寸约定（1x / @2x）

每张图在磁盘上可以有两份，引擎会自动挑清晰的那份（`Assets.ts` 的 `hiPathOf` 优先读 `<名字>@2x.png`），
**两份的图片内容必须完全一样，只是分辨率不同**，所以换主稿不需要改代码、也不会改变画面大小：

| 文件 | 应该是多大 | 说明 |
| --- | --- | --- |
| `<名字>.png` | **= `ART` 表里写的设计尺寸** | 和 `Assets.ts` 的 `w`/`h` 一致，便于核对 |
| `<名字>@2x.png` | **= 设计尺寸 ×2** | 高分辨率屏 / 拉近镜头时的清晰度来源 |

全局规则：**一律 2×**（不因为镜头放大而单独做 4×，那是冗余分辨率）。当前背景层的实际尺寸：

| 素材 | 1x（设计尺寸） | `@2x` 主稿 |
| --- | --- | --- |
| `d01_sky_day` / `d02_sky_dusk` / `d03_sky_night` | 1280×720 | 2560×1440 |
| `b09_daluo_mountain` | 160×380 | 320×760 |
| `b10_outer_salt_flat` | 560×60 | 1120×120 |
| `b11_coast` | 260×80 | 520×160 |
| `d06_horizon_silhouette` / `d08_mid_houses` | 1280×160 | 2560×320 |

条带类（`b10`/`b11`/`d06`/`d08`）按原比例铺满堤岸，**不压扁**：1x 与 @2x 的宽高比必须相同。

自查：`python tools/audit_2x.py`（谁缺 `@2x`）、`python tools/audit_scale.py`（各自的实际像素与显示尺寸）。
